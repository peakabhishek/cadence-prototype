# Cadence for iPhone: visual direction options (cadence#54)

Iris (Design), 26 Nov 2026. **Provisional until Abhishek approves a direction.** Fake data only. Issue: [peakabhishek/cadence#54](https://github.com/peakabhishek/cadence/issues/54). Spec: Steve’s Notion spec ([§4.3 parked rule](https://app.notion.com/p/4240cf07a80181748457fe2ab43ca898)).

All three options start from the shipped Windowsill look (v1.2.0: `web/tokens.css`, money-plant SVGs from `web/plants/`, the laptop handoff in `focus-tracker/handoff/`). iPhone 390×844 frames at @2x with the Dynamic Island, status bar and home indicator.

**Why B leads.** Abhishek decided (26 Nov, 9:23 PM IST) that Cadence for iOS is an installable app: a Capacitor wrapper or native Swift, not picked yet. It is no longer a PWA. B uses only patterns that both build paths can draw the same way: the system font stack, large title, tab bar, inset grouped lists and sheets. It keeps the approved Windowsill colours and plant, so the Mac and the iPhone read as one product, and Dynamic Type comes almost free. A is the safest port but feels like a web page on iPhone. C is a strong mood, but it brings a new dark palette that nobody has approved yet.

**For the build (lead option B, provisional):**
- [`ios-tokens.css`](ios-tokens.css) extends the approved `tokens.css` and doesn’t fork it: colour roles, system font stack with the iOS text styles, spacing, radius, safe-area insets and the demo banner. B has no dark mode.
- [`component-specs-ios.md`](component-specs-ios.md) covers the tab and nav bars, goal list and row, add-goal sheet, Parked group and Move in, focus timer, sync states, MOCKED first-run sign-in, sign-in expired, the demo banner, and the empty, loading and error states. §11 lists where Capacitor and Swift differ: keyboard, status bar and safe areas, haptics, and system sheets.
- [`contrast.md`](contrast.md) has the WCAG checks for all three palettes, generated by `src/palettes.py`. Every text pair passes AA (4.5:1), and every UI pair passes 3:1.

## Spec assumptions (Steve, 26 Nov; Design didn’t decide these)

- The phone shares the Mac’s goals: same IST day, same 6-goal limit.
- Offline is in scope. Adding and ticking goals works offline and syncs later.
- A goal can be edited on both devices, and the conflict is resolved with no data loss.
- No notifications, widgets or Live Activities in v1.
- v1 is today’s goals plus focus sessions, for Abhishek only. The phone shows today only, with no past-day screens.
- Over 6 goals after a merge: the day keeps its first 6 by commit time, goals already showing never move, and only the late-arriving goal is parked ([spec §4.3](https://app.notion.com/p/4240cf07a80181748457fe2ab43ca898), [#54 rule](https://github.com/peakabhishek/cadence/issues/54#issuecomment-7196971740)).
- Distribution: v1 installs through a local Xcode build on Abhishek’s Mac. The Apple Developer account is on hold, so the TestFlight upload is blocked. This doesn’t change the design.

## Open questions for Steve’s spec (not decided here)

1. **Build path:** Capacitor wrapper or native Swift. B works for both; see the differences in component-specs-ios.md §11.
2. **Sync:** how the phone reaches the OneDrive file (Microsoft Graph directly, or through the Mac). Also: whether “Waiting for your Mac” and “Mac needs an update” (schema version) are real states, how clock skew is corrected, and whether a conflict keeps whole versions (as mocked) or merges field by field.
3. **Offline:** what is cached on the phone, and what the first open with nothing cached shows (frame 08). Also: limits on queued edits, and how queued edits survive a reinstall when the free install expires after 7 days (Steve’s acceptance check).
4. **Ticking a goal:** what a tick means next to the shipped “hit” rule, where finished minutes have to reach the time box.
5. **Focus on iPhone:** what happens when the phone locks or the app goes to the background, given the Mac’s 10-minute sleep rule. Also: whether a session can run on both devices at once.
6. **Notifications, widgets, Live Activities:** out of v1 (assumption). Is it acceptable for a session to end with no alert?
7. **Apple Developer account:** cost is Abhishek’s call and the account is on hold. Until then: local Xcode installs only, and no TestFlight.
8. **Data privacy (DPDP):** the Microsoft sign-in scope (one folder or all of OneDrive), what is stored on the phone and in logs, and what Friday reads. No health data.
9. **Dark mode:** B is light-only. Is dark needed in v1? C’s night palette is the candidate.
10. **Past days:** the end screen says the plant “joins Thursday’s grove” but has no link, because there are no past-day screens in v1. Confirm.
